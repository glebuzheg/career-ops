# Поиск вакансий в России

В этой ветке добавлены четыре подключения. Все они возвращают вакансии в
обычный pipeline Career Ops; оценка и подготовка резюме работают как раньше.
Отправка откликов остаётся за пользователем.

| Источник | Подключение | Что требуется | Проверка |
| --- | --- | --- | --- |
| hh.ru | `provider: hh` | Публичный API, без ключа для поиска | Тесты; из текущей среды API отвечает HTTP 403 |
| Хабр Карьера | `provider: habr-career` | Публичная страница `/vacancies` | Живая проверка: 25 вакансий по Python на первой странице |
| SuperJob | Плагин `superjob` | Secret key зарегистрированного приложения | Тесты на примерах API; без ключа сервер отвечает HTTP 403 |
| Hirify | Плагин `hirify` через MCP | Настоящий адрес MCP из личного кабинета и авторизация | Проверен MCP-протокол на тестовом сервере; живое подключение пока не проверено |

## Быстрый старт

На новой установке скопируйте `templates/portals.russia.example.yml` в
`portals.yml`. При существующей конфигурации перенесите нужные `job_boards` и
проверьте `title_filter` / `location_filter`: фильтры исходного международного
примера могут исключать российские города. Замените Python во всех запросах
на свою специальность.

```bash
node validate-portals.mjs --file portals.yml
node scan.mjs --dry-run
node scan.mjs
```

`--dry-run` проверяет запросы без добавления результатов в pipeline. Обычный
запуск применяет стандартные фильтры и дедупликацию. Источник может обрезаться
на `max_pages`; сообщение об этом не означает, что собраны все вакансии.
Если площадка возвращает CAPTCHA/403, сбор сообщает ошибку без обхода защиты.

## HeadHunter

В `hh:` поддерживаются `text`, `area`, `experience`, `employment`, `schedule`,
`professional_role`, `employer_id`, `salary`, `currency`, `only_with_salary`,
`period`, `date_from`, `date_to`, `search_field`, `order_by`. Значения берите из
[документации HH](https://api.hh.ru/openapi/redoc#tag/Poisk-vakansij).
Регион 113 — Россия, 1 — Москва, 2 — Санкт-Петербург. Несколько значений можно
задать YAML-массивом. Поддерживается и поисковая ссылка `hh.ru/search/vacancy`.

До 100 записей за запрос, по умолчанию до 5 страниц, максимум 20. Ограничение
HH на выдачу одного запроса — 2000 результатов: сужайте запрос по региону,
профессии и датам. Для каждого региона/запроса можно создать отдельную запись.
Публичный поиск не требует пользовательского OAuth; доступ зависит также от
ограничений самого HH. Ошибка 403 не означает отсутствие вакансий.

Ссылки `/employer/...` и отдельные вакансии не считаются поисковой выдачей.
Для конкретной компании используйте `hh.employer_id`: иначе можно случайно
собрать весь рынок вместо вакансий этого работодателя.

## Хабр Карьера

Задайте `habr: { q: "Python" }` либо скопируйте публичную поисковую ссылку в
`careers_url`. Поддерживаются `q`, `type`, `order`, `city_id`, `remote`, `salary`,
`currency`, `qid`, `employment_type`, `company_id`, `skills[]`. По умолчанию
`order=date`, 5 страниц, максимум 50. Считывается JSON, встроенный в HTML
публичной выдачи, без обращения к закрытым API, входа в аккаунт или Chromium.

Ссылки `/companies/.../vacancies` и отдельные вакансии не перенаправляются
в общий поиск. Используйте поисковую ссылку и `habr.company_id`.

Суммы зарплат HH, Хабра и SuperJob пересчитываются из месячных в годовые для
существующего `salary_filter`. Это не конвертация валют и не расчёт зарплаты
после налогов. Неуказанные суммы не подставляются.

## SuperJob

1. Зарегистрируйте приложение на <https://api.superjob.ru/register/>.
2. Сохраните Secret key в своём `.env`: `SUPERJOB_APP_KEY=...`.
3. Добавьте в `config/plugins.yml`:

```yaml
plugins:
  superjob:
    enabled: true
```

4. Включите запись `provider: superjob` в `portals.yml`. Поисковые поля
   задаются в `superjob:`; например `keyword: Python`, `town: 4` для Москвы.

Плагин использует официальный API с заголовком `X-Api-App-Id`. Пароль от
аккаунта соискателя не нужен. Без ключа интеграцию невозможно проверить на
живых данных; тесты используют форму ответа из документации.

## Hirify MCP

1. Откройте <https://hirify.me/account/mcp-api> и скопируйте **адрес сервера**
   из настройки MCP, а не адрес самой страницы кабинета.
2. Сохраните в своём `.env`:

```dotenv
HIRIFY_MCP_URL=адрес-Streamable-HTTP-сервера-из-кабинета
# Только если настройка требует Authorization: Bearer:
HIRIFY_KEY=ваш-ключ
```

3. Добавьте `hirify: { enabled: true }` в блок `plugins` файла
   `config/plugins.yml` и включите запись `provider: hirify` в `portals.yml`.
4. Задайте `hirify.query`. По умолчанию запрашивается одна страница. При
   нескольких поисковых инструментах укажите `hirify.search_tool` с именем
   из `tools/list`; при нестандартном поле запроса — `hirify.query_field`.
   Дополнительные фильтры задаются в `hirify.arguments` по схеме сервера.

Ключи, лимиты и названия фильтров не зашиты в код. Используются только поиск и
его карточки; чтение полных вакансий, раскрытие контактов и отправка откликов
не вызываются. Они имеют отдельные лимиты Hirify. Нестандартная схема ответа
вызывает понятную ошибку вместо ложного «вакансий нет».

Поддерживается стандартный MCP Streamable HTTP (JSON/SSE), а не старый SSE
transport с отдельными адресами чтения/отправки. Авторизованный MCP Hirify
в этой сессии не был доступен: потребуется проверить фактическую схему и
настройки на своём аккаунте. Наличие MCP у сервиса само по себе не означает,
что он уже подключён к этому форку.

## Диагностика

```bash
node plugins.mjs list
node doctor.mjs
node audit-portals.mjs --help
```

Плагины выключены по умолчанию. Секреты и персональные конфиги не входят в
коммит. Не публикуйте содержимое `.env`, приватный MCP URL или ключи в issue.
